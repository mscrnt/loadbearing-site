Support

EARLY ACCESS · ONE-DEVELOPER STUDIO · EMAIL-FIRST

The short version

Pick the channel that fits your situation — bug tracker for known issues and dupe-checking, Steam discussions for casual conversation, email for anything private. Load Bearing is built and supported by one person (mscrnt). There is no support phone line and no live chat, and I read every message myself. Expect a reply within about a week during Early Access, faster after 1.0.

Where to file

Three channels, choose the one that fits:

  • GitHub Issues → github.com/mscrnt/loadbearing-issues
    Best for bug reports. Public, searchable, dupe-checkable — see if your crash is already filed before writing a new one. Issue templates prompt you for the fields I need (build, OS, repro). Requires a free GitHub account.
  • Steam Community Hub → steamcommunity.com/app/4883800
    Best for general discussion, balance threads, "is anyone else seeing this?" before formally filing. Uses your existing Steam account; no extra signup. I read every thread but technical issues move faster on GitHub.
  • Email → hello@loadbearing.games
    Best for anything private: refund coordination, sensitive bug reports, anything you don't want public. Catch-all if the other two feel like too much friction.

Reporting a bug — what to include

Copy this template into your email; it saves a round-trip:

  • Build: the version shown in the bottom-right of the main menu (e.g. 0.1.0 · b1).
  • OS: Windows 10 / Windows 11 / macOS 14 / Ubuntu 22.04 / Steam Deck, etc.
  • What happened: one or two sentences, plain language.
  • What you expected to happen.
  • Steps to reproduce: "open the game → click X → wait Y seconds → crash." If it only happens sometimes, say so.
  • Log file: attach it (see below). It's plain text; you can open it first if you want to check.
  • Screenshot or short clip if the bug is visual.

Finding your log file

Easiest route: in-game, open Settings → About → Open log folder. That opens the right directory for your OS. If that menu isn't available in your build yet, the log lives here:

  • Windows: %APPDATA%\Load Bearing\logs\ — paste that into File Explorer's address bar.
  • macOS: ~/Library/Application Support/Load Bearing/logs/ — in Finder, Go → Go to Folder… and paste it.
  • Linux / Steam Deck: ~/.local/share/Load Bearing/logs/

The file you want is the most recent godot.log. It contains gameplay events, errors, and timing info — no personal data, no IP, no account info, nothing typed in-game. You can read it before attaching.

Common issues

Game won't launch

Update your graphics drivers — Godot 4 requires reasonably current GPU drivers for Vulkan. On Windows, also try right-clicking the game in your Steam library → Properties → Installed Files → Verify integrity of game files. If it still won't start, email the log file from the path above (it captures startup failures even when the window never opens).

Save file looks wrong after an update

During Early Access, save format may change between builds. The game auto-backs-up your previous save before any migration; check the saves/ folder next to logs/ for a *.bak file. If a migration ate something it shouldn't have, send me the backup and tell me which build wrote it.

Crash mid-run

The log file pinpoints these. Attach it, plus the time of day the crash happened (so I can find it in the log) and roughly what you were doing (which map, which upgrades, idle vs. active).

Stuck on a map or balance feels wrong

Not a bug — but absolutely worth telling me about. Balance feedback is the most useful thing you can send during Early Access. Map number, attempts, what you tried, what felt unfair. The opt-in telemetry on the privacy page also helps here, but a written "I quit map 7 because…" is worth ten thousand data points.

Refunds

All refunds go through Steam, not through me — I cannot issue or block refunds on a Steam sale. Steam's standard policy (under two hours played and under 14 days since purchase) covers most cases automatically:

Request a refund on Steam →

If you're past the standard window because a bug blocked you from playing, include that in your refund request to Steam and feel free to email me separately — I can confirm the bug to Steam support if they ask.

Privacy

Sending a log file or screenshot is voluntary, and the data in those files is gameplay-only — see the privacy policy for the full list of what the game does and does not collect. If you're not comfortable attaching a log, describe the issue and I'll see what I can do without it.

Early Access reality check

Load Bearing is in Early Access. That means: things will break, balance will shift, features will land on the roadmap before they land in the game, and some bugs will take a while to fix because there's one developer and a finite number of hours in a week. I will be honest with you about what's a known issue, what's actively in progress, and what's a "yes but not this month." Polite, specific bug reports get fixed first.
